# MOOTECH 素材目錄與交付標準 · v1

此標準適用 mootech-asia 的 cms_system、mootech_website、bo_system、Informatica-Administrator。活動、網站、管理後台與品牌包遵循同一套分類、編號及交付原則；專案既有的技術架構、部署根目錄與資料庫不因素材整理而改變。

## 分類與命名

| 分類 | 正式目錄（相對於該功能的靜態資源根目錄） | 編號 | 製作用途 |
|---|---|---|---|
| 圖片 | `assets/images/` | IMG001 | 場景、三語主標、介面、圖示、角色、分享圖 |
| 背景音樂 | `assets/music/` | BGM001 | 可循環背景曲 |
| 音效 | `assets/sounds/` | SFX001 | 選擇、點擊、開啟、翻牌、揭曉、領獎、失敗 |
| 視覺特效 | `assets/effects/` | VFX001 | 粒子、風沙、星光、光暈、反光與特效貼圖 |
| 3D | `assets/3d/textures/`、`assets/3d/models/` | 3D001 | 各面貼圖、GLB 等網頁模型；模型實檔存在才建立 models |
| 字型（有需求才使用） | `assets/fonts/` | FNT001 | 授權字型；保留字型分段／CSS 的必要檔名契約 |
| 影片（有需求才使用） | `assets/videos/` | VID001 | 首屏循環影片、角色影片；靜態 poster 歸 images |

- 正式檔名：`專案或活動名稱_分類編號_用途描述.副檔名`，例如 `card_pack_3D001_pack-front.webp`、`mootech_website_VID001_hero.mp4`。前綴用英文小寫與底線；編號在同一功能／分類內唯一、既有編號不重排。
- 可編輯原稿、分層檔、母帶、角色設定、序列幀與授權放 `source/<相同分類>/`。原稿包外層加前綴與來源編號，內部關聯檔名、UV、骨架及 frame 順序保留。
- CSS、JS、API、資料庫、第三方 library 不因素材分類而搬移；程式生成的動態或 3D 幾何登錄程式來源，不建立假的影片／模型。
- 有實際素材才建分類子目錄；不放空模型、靜音音檔、假素材、.gitkeep 或無用途空目錄。素材製作清單明確列出「不適用」。

## 登錄、製作與換主題

1. 根目錄 `ASSET_MANIFEST.json` 是 repo 層級素材登錄資料；`docs/ASSETS.md` 由 `python3 tools/assets.py catalog` 產生，列出編號、實際路徑、用途、尺寸／格式、透明、狀態及原稿。
2. 動工前先依用途建立槽位和製作清單，不能只複製幾張圖片。`python3 tools/assets.py brief --name <功能名稱>` 可產生空白製作清單；`--from-prefix <既有前綴>` 可繼承該功能已登錄的完整素材槽位。新活動應優先使用 repo 已有的玩法範本；cms_system 使用 `scripts/event-assets.py init --from <活動資料夾> --name YYYYMMDD_event_name`。
3. 每項至少記錄用途、交付路徑、格式、尺寸、透明需求、動畫時間／幀數或音訊長度（適用時）、程式引用與原稿來源。待製作、程式生成、共用引用、已交付要明確區分。
4. 同玩法換主題時維持畫布、尺寸／比例、透明區、定位錨點、UV、骨架契約與循環時間；只換圖與色票即可換視覺。日期、次數、獎項等動態文案由程式疊字；對外有多語系的活動主標各語系獨立交付。
5. 改模型輪廓、UV、骨架、互動邏輯或玩法時需同步修改程式與驗證，不得宣稱只換圖即可完成。
6. 共用素材只保留一份來源，清單列出跨功能與跨 repo 的引用，避免複製後各自失去同步；第三方品牌／library 保留授權與官方內部命名。

## 既有路徑契約

已發布且由其他版本、跨 repo、品牌包、動態檔名或框架資源管線引用的路徑，可以保留一份既有正式檔；必須在清單標記 `pathPolicy: contract`、用途與 `preserveReason`，不能為了命名再複製一份圖。這是可追蹤的相容契約，不代表該檔已改成新檔名。新加素材必須採新規格，不能默認沿用例外。

原稿包、品牌包和設計驗證證據保留關聯內部命名並列管；驗證截圖不算新美術交付。Node 的 public、靜態網站子目錄、獨立版本各自以真正的部署根目錄為基準，不強迫把它們移到 repo 根目錄造成 404。

## 清理與驗證

- 先確認 HTML、CSS、JS、config、metadata、srcset、動態組合檔名、跨 repo 引用及發布流程，再搬移並同步改引用。
- 淘汰版本、已確認相同內容的壓縮包、快取、一次性輸出直接從工作目錄移除，歷史由 Git 回溯；保留現行可編輯原稿、授權、必要設計文件及有用途的公開相容路徑。
- 執行 `python3 tools/assets.py check`：檔案缺漏、未登錄素材、重複編號／路徑、指紋變更、未說明的舊路徑或待製作項目應攔截。子系統有獨立清單時需一併檢查，不重複維護兩份。
- 修改圖檔後先核對尺寸、透明、動畫／UV，再更新清單指紋；不能用空檔繞過交付檢查。
- 只有文件／工作守則修改時驗相關差異；搬動 runtime 素材時驗實際部署路徑、手機／桌機、相關語系與互動，並與原畫面比對。原稿不能加入網站首屏或發布包。

## 自動檢查

各 repo 的 `.github/workflows/asset-standard.yml` 在素材或清單變更時執行同一個缺檔／編號／指紋檢查。已登錄的公開路徑契約可保留；未登錄的新素材會失敗。
