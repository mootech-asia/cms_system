# 資料表格（投注記錄/交易記錄/盈虧明細這類頁面）

本 repo 像 `betting-record.html`／`deposit-record.html`／`withdrawal-record.html`／
`profit-loss.html` 這類頁面用的是真的 `<table>`（`record-table` class），不是
div 疊出來的假表格。以下是純前端就能做到、不需要後端支援的規則：

## 表頭

- **表頭跟內文要是看得出來的兩種底色，不是只換個色相**：實際量測明度差
  （ΔL* ≥ 5，深色主題大約抓表頭比內文淺 10–20%），不要只靠肉眼覺得「有換色就好」——
  同色相不同飽和度在螢幕調暗時常常糊成一片，這是連正式產品都踩過的坑。顏色一樣要
  從本版本既有 token 裡挑，不是另外調一組新色碼。
- 表頭文字對表頭底色至少 **7:1**（比一般內文的 4.5:1 更嚴），粗體、置中、
  letter-spacing 微調（全大寫/轉繁體標題時常見）。
- 表頭欄位之間用**半高、低調的直向分隔線**，不要拉滿整個儲存格高度——拉滿會讓表頭
  整塊看起來像網格，跟表頭下緣那條分隔線互相打架。

## 數值欄位

- 數字欄位（金額、賠率、盈虧）一律**右對齊 + 等寬數字**（`font-variant-numeric:
  tabular-nums`，第三層「打磨細節」已經提過等寬數字，這裡是延伸到「整欄對齊」）——
  數字要能上下對齊比大小，不是只靠等寬字體不跑位。欄位標題本身仍維持置中，只有
  數值內容右對齊。
- 一般文字/狀態/日期欄位置中對齊；需要換行的長文字欄位（備註、遊戲名稱過長時）
  改左對齊——置中的多行段落兩邊都參差不齊，比左對齊更難讀。

## 日期/時間欄位

- 這個 repo 本來就是多語言站，日期顯示格式要在同一個頁面裡**從頭到尾一致**，月份
  名稱（如果顯示英文月份縮寫）要跟著當前語言走，不要中文介面混英文月份、或反過來。
  這是純粹的一致性規則，不是要改資料本身的儲存格式——跟 `references/i18n-layout.md`
  那條「不要順手改格式」是同一條界線：只整理顯示上的一致性，不改變數字/日期代表的
  實際值。
- 如果一筆記錄同時有日期跟時間（例如交易時間精確到時分），時間放在日期**下面
  一行**，不要直接接在日期後面擠成一串——擠在一起的 `2026-10-2714:35` 對螢幕閱讀器
  跟複製貼上都會黏成一串無法正確分開的文字，日期欄位通常是不該被擠壓到換行的欄位，
  接在後面常常把整欄撐寬超出版面。

## 長內容與窄螢幕

- 儲存格長文字（備註、遊戲名稱）設定**最多顯示 3 行**再用 `...`，hover 時才顯示完整
  內容——只對真的被截斷的儲存格做這件事，沒被截斷的短內容不要無意義地冒出 tooltip。
- 手機寬度下表格會橫向捲動時，**第一欄（通常是日期或單號）用 `position: sticky`
  固定在左側**，捲動時使用者才不會對不上這筆記錄是哪一天/哪一筆。如果該表格有「操作」
  欄（例如交易記錄的「查看明細」按鈕），一樣可以固定在最右側，並給它不透明背景，
  不然底下捲動的儲存格內容會透出來蓋到按鈕上。這兩條都只是 CSS `position: sticky` +
  既有 token 的背景色，不需要額外的 JS 邏輯。

## 排序（只有該頁面本來就有互動排序功能時才適用）

本 repo 目前這類記錄頁面大多是伺服器端/靜態排序好的資料，沒有前端互動排序。**如果**
之後有頁面真的要加「點表頭排序」這種互動功能，才需要以下兩條，不要為了套用規則
反過來無中生有加排序功能：

- 排序中的那一欄表頭加一條底色強調線（例如 2px 色條，用既有 accent token），不要只
  靠一個小箭頭——箭頭在螢幕調暗時很容易被忽略，使用者會搞不清楚目前是依哪一欄排序。
- 有搜尋框的地方，搜尋圖示放在輸入框左側、清除（✕）按鈕放在右側，兩者不要互相重疊，
  且清除按鈕要真的把篩選條件清掉、不是只清空輸入框文字卻保留篩選結果。
