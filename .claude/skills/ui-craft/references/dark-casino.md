## (A) 深色主題：深度要靠「亮度」做，不是硬反轉

本 repo 多版本有多套 `data-skin` 色板，部分是深色系。做深色不是把淺色主題
色碼機械式反轉（第一層 `systems.md` 已講「不要反轉 ramp」），而是：

1. **底色用深灰而非純黑**：Material 建議深色表面用 `#121212` 這類深灰，不用
   純黑 `#000`。純黑對比過猛、看久眼睛累，且純黑上看不到任何陰影，分層全失。
   本 repo 要沿用該 skin 既有的底色 token，不要自己塞 `#000`。
2. **分層靠「越上層越亮」**：深色沒法用陰影做深度（黑底上陰影看不見），改用
   **越高的表面越亮一點**（Material 的做法是疊一層越來越不透明的白色半透明
   overlay）。彈窗 > 卡片 > 底，用亮度階差表達，不是全部同一個深色。
3. **強調色去飽和**：高飽和的亮色放在深底上會「視覺震動」（刺眼、邊緣發抖）。
   Material 建議深色模式用**較低飽和**的色階。本 repo 要用該 skin 既有的
   強調色 token 的對應階，不是把淺色主題的高飽和主色直接搬過來。
4. **正文對比拉高**：深底上正文對比要夠（Material 範例把 on-surface 文字對
   底色做到很高，約 15.8:1 等級）；一般仍至少守 AA 4.5:1，正文用高明度白但
   常以 ~87% 不透明度（高強調）／~60%（中強調）分層，不是每段都純白。
5. **大面積彩色要收斂**：深色模式避免大面積高飽和填色，容易累。大色塊降
   飽和/降明度，彩色留給需要被看見的強調點。

深色主題驗收：分層是不是靠亮度階差（不是陰影）？強調色有沒有去飽和、不震動？
正文對比夠不夠？所有值是不是該 skin 既有 token、沒有自己塞 `#000`/高飽和色？

## (B) 博弈/電玩視覺語言（我的綜合，非權威來源）

搜不到可引用的公開方法論，以下是結合一般視覺原則與本 repo 既有 skin 做法的
建議，請當作起點、可被推翻：

1. **光感/金屬質感用既有 token 疊，不新增色碼**：喜慶紅金這類 skin 的「發亮/
   金屬」感，靠既有金色色階的**多階層次**（暗金→亮金→高光）＋第三層的多層
   陰影（cast + contact）＋克制的漸層做出來，不是新增一堆 `#FFD700` 類寫死
   金色。這條被第一層 token 鐵則直接管住。
2. **對比節奏製造「重點」**：博弈頁的獎項/金額/CTA 本來就該是視覺焦點——用
   第二層「一次只放大一件事」＋尺寸/亮度對比把它頂出來，而不是整頁每個區塊
   都一樣亮一樣滿（那是第二層講的「每區塊長一樣」通病）。
3. **動效/特效題材上站得住腳、但仍限量**：第三層已確認這個題材（博弈/電玩＋
   金融科技）適合用 scroll/光效類效果——但單頁仍只配一到兩個記憶點等級的
   效果，不是每個卡片都發光跳動。獎勵/中獎類的慶祝動效要短（<300ms~數百ms
   一輪）、可被 `prefers-reduced-motion` 關掉。
4. **「貴/興奮」不等於「亂/廉價」**：金光＋紅＋發光堆到滿版，結果常是第一層
   說的「看起來很廉價」。興奮感靠對比節奏和克制的高光點，不是密度。瞇眼測試
   （`craft-polish-motion.md`）：瞇起來還能看出哪裡是重點，就過；一片亮糊成
   一團，就是堆過頭。
5. **不碰合規/內容**：賠率、金額、活動條款、法遵提示這類文字/數字一律逐字
   保留（第五、七層紅線），視覺再炫也不改一個字、不改一個數字格式。

博弈視覺驗收：金屬/光感是不是用既有金色 token 疊階做的、沒有新增寫死色碼？
重點（獎項/金額/CTA）有沒有真的靠對比頂出來？特效有沒有限量、能不能被
reduced-motion 關掉？瞇眼看是不是還有重點、沒糊成一團？賠率/金額/條款有沒有
被動到？
