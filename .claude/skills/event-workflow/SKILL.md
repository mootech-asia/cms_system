# 活動頁工作流（mock up → 製作美術圖 → 套用）

範本：`event/20261111_lucky_wheel/`。新活動先讀它的 `DESIGN_TASKS.md`、`GPT_ASSET_BRIEF.md`、
`DELIVERY_CHECKLIST.md`、`assets/js/*.js`，照同樣結構做，不要重新發明。

## 第 0 步：開資料夾

- 命名 `event/YYYYMMDD_event_name[_N]`（英文小寫底線；同日同名才加 `_2` 起的編號），並在 `event/README.md` 活動列表加一列。
- 結構：`index.html`、`DESIGN_TASKS.md`（美術需求）、`GPT_ASSET_BRIEF.md`（給 GPT 的步驟與提示詞）、
  `DELIVERY_CHECKLIST.md`（交付勾選表）、`reference/`、`assets/{css,js,img}`。
- 免建置純 HTML/CSS/JS；CSS 用 token（`:root` 變數），不寫死任意色碼。

## 第 1 步：mock up（先能玩、先能看）

1. **每一個視覺元件都是「可換的圖片槽」**，不是只有主圖：背景（手機＋桌機）、底紋、主標、按鈕、彈窗、
   徽章/標籤、卡片外框（九宮格）、卡片標題緞帶、頁尾裝飾、圖示、分享預覽圖、吉祥物動態。
   路徑集中在 `assets/js/config.js` 的 `images`，換圖＝同檔名覆蓋或改 config。
   - 背景類用 `data-img`；需要桌機版的加 `data-img-desktop`（≥768px 自動切換）。
   - 元件底圖用 CSS 變數 `--ev-img-<key>`，由 JS 從 config 寫入。**`url()` 放進 CSS 變數時要先轉絕對網址**
     （`new URL(src, document.baseURI).href`），否則會以樣式表位置解析而 404。
2. **圖上不放會變的文字**：按鈕、彈窗、徽章文字一律程式疊字；只有活動主標是「每個語系一張圖」。
3. **後台內容只留空位＋假資料**（轉盤類：獎項數量／名稱／圖示／機率／可選扇區色都由後台給，扇區由程式畫，美術只出外框與色票；
   內部預覽用 Ctrl+Alt+↑／↓ 增減獎項數量；內部面板手機與電腦同一個、同樣叫法：畫面同一位置連點三下（手指或滑鼠）。用「每下間隔 ≤0.5 秒」串接判斷，不可用「三下總時間」（實機常超過 0.6 秒），點在按鈕上不算）：獎項、規則、次數等由我們的後台提供（`window.EVENT_CONTENT`，格式寫在
   `store.js` 開頭）。mock 用 config 的 `defaultContent` 假資料；後台沒給時要有空狀態（例：規則區虛線空位）。
   不要自己做後台。
4. **語系**：前台只有 en/ko/th（預設 en）；zh 只供內部預覽，Ctrl+Alt+L（Mac：Control+Option+L）切換，
   不在選單、焦點在輸入框時不觸發；缺翻譯退回 en，絕不退回 zh。分頁標題固定英文。
   **任何對外可見的地方都不得有中文**——含 alt/aria、toast、換圖標籤、佔位圖、分享文案。
5. **舞台／場景美術方向**：預設做成**有角度、有透視的 3D 世界觀**（地板有縱深與透視線、側牆往內收、光圈打在地板），
   不要正面平面背景；背景以「貼齊底部、等比填滿」顯示，地板放下半部。**真實空間感**：主要道具（例如轉盤）要有底座
   立在地板上；吉祥物站在道具**前方**（顯得較大，但只擋道具一點點：轉盤案例約 3% 盤面，可用「隱藏/顯示吉祥物截圖比對」量測）；光源統一（前上方偏左）；接地陰影由程式加，
   素材不畫地面陰影；互動按鈕（例如 SPIN）不可被吉祥物蓋住，吉祥物容器設 `pointer-events: none`。
6. **第一屏要有完整操作**：主要道具（轉盤）下方做操作台（中獎跑馬燈＋剩餘次數＋主行動大按鈕），手機 360×640、
   桌機 1280×720 起第一屏就看得到；道具尺寸用 `min(寬, 高)` 依螢幕高度縮放；吉祥物用 absolute 疊在操作台後方，不佔版面高度。
   含長文字的 grid/flex 子項要 `minmax(0,1fr)`／`min-width: 0`，否則會被撐到畫面外（overflow hidden 時看不到也不會出現橫捲）。
   **版面寬度**：**只用 H5 寬度展示**（2026-11-11 使用者定案）：`body` 限寬 480px 置中，桌機兩側是素色底
   （token `--ev-color-backdrop`），不做全螢幕、不做桌機版背景；背景圖只出手機版。
   **鎖直向**：網頁無法真正鎖螢幕方向（`screen.orientation.lock` 只在 Android 全螢幕／已安裝有效，iOS 不支援），
   所以呼叫 lock（失敗靜默）＋觸控裝置橫向矮螢幕（`orientation: landscape` 且 `max-height: 540px` 且 `pointer: coarse`）
   蓋上「請轉直向」提示層（三語文字＋可換圖示 `icon-rotate`）；桌機視窗再矮都不觸發。
6-2. **影子與音效**：主要道具（底座）腳下要有接地陰影，且**不可被操作台蓋住**；另加柔和 drop-shadow 增加立體感。
   **吉祥物不用程式加陰影**（試過貼身 drop-shadow、腳底接觸陰影、用同一 GIF 做會擺動的地板投影，使用者評「太爛」）；
   2026-11-12 起改成**影子由美術畫進角色素材**。
   **道具（轉盤）影子要先看清楚場景再做**：截圖看牆腳線、道具離牆多遠、光源方向。轉盤立在離背牆很遠的地板上 → 不要用貼牆的 drop-shadow，
   改成地板上被壓扁的盤面投影（往光源反方向、大半被盤面擋住）＋立柱投影＋底盤接觸陰影，全部是靜止元素；先用紅色填滿確認位置再調透明度。中獎跑馬燈蓋在吉祥物上（z-index 高於吉祥物）。音效：轉動鼓聲、停止大鼓＋鈸、
   **開獎彈窗出現時要有獎賞聲**（中獎琶音、未中獎柔和下行），未交付音檔時用 Web Audio 合成，關閉音效時全部靜音。
   獎賞聲音量要和鼓聲同一量級（攔截 destination 量 RMS 驗證，不可只看「有排程」），前一段鈸聲餘音不可蓋住它；
   第一次使用者操作時播無聲 <audio> 解除 iOS 靜音鍵對 Web Audio 的靜音。
   頂部語系／分享／音效列浮在場景上（absolute），不佔版面高度，主視覺往上提。
7. **分享活動網址**（每個活動都要）：分享面板（系統分享、複製連結＋手動複製 fallback、LINE/Facebook/X/
   WhatsApp/Telegram）、網址帶 `?lang=`（zh 預覽一律分享 en；切語系時改寫網址參數）、og/twitter meta 指向
   1200×630 **PNG/JPG**（社群不吃 SVG）。可直接複製 `assets/js/share.js`。KakaoTalk 需官方 SDK 金鑰，未做。
8. **吉祥物要夠大**：站在舞台地板上、全身入鏡，手機角色寬約 200px、全身約 360px 高（畫布約內容欄 95% 寬），不要縮在角落。
   狀態：待機 ×3（輪播）、期待（進行中）、慶祝（中獎）、失望（未中獎；未交付時程式先用慶祝），各一段循環動態。
   **角色影子畫進素材本身**（腳底接觸影＋往光源反方向的柔和投影，跟著動作變化），主交付是 RGBA PNG 序列幀，
   網頁用 `tools/gif_to_webp.py` 由序列幀轉動態 WebP（保留半透明影子）；GIF 只當預覽。任何一幀都不可貼到畫布邊緣
   （`check_delivery.py` 逐幀量外框，四邊 ≥8px），每段總長必須 2000ms。
9. **換圖標籤**：每個圖片槽旁顯示「檔名 · 尺寸」（英文），放角落/空白處不壓內容，內部面板可關閉。
   佔位圖本身**不要把尺寸字樣畫進圖裡**，佔位文字不可超出框。
10. **內部面板**（獎項數、重設次數、換圖標籤開關）**預設隱藏**，手機與電腦都用畫面連點三下叫出／收起（sessionStorage 記住，新分頁又隱藏），不另設鍵盤快捷鍵或頁底工具列；
    「重設次數」給 `config.mockResetSpins`（本案 10 次）方便內部連續測試，不改後台的 freeSpins。上線前整段拿掉，寫進需求單的「上線前」清單。

## 換皮（同一個活動程式做不同主題）

- 活動建好後，新主題＝新皮：`skins/<名稱>/` 放 `skin.css`（只覆寫色票）、`img/`（只放跟預設不同的圖片槽）、
  `DESIGN_TASKS.md`／`GPT_ASSET_BRIEF.md`／`DELIVERY_CHECKLIST.md`（交付路徑以皮資料夾為基準）。
- `config.js` 的 `skins.<名稱>` 列出圖片槽覆蓋與 css；`assets/js/skin.js` 依 `config.skin` 或網址 `?skin=` 套用，
  色票載入後發 `ev:skin` 讓轉盤重畫扇區顏色；分享連結會帶上非預設的 skin。
- 新皮先做 mock（佔位 SVG＋色票，指紋加進 `check_delivery.py`），再開需求、交 GPT。
- **仿某作品風格時**：可以貼近類型氛圍，但需求單要寫明禁止元素（作品名稱／標誌、招牌符號組合、招牌服裝道具），
  改名不等於原創；本案範例見 `skins/survival/DESIGN_TASKS.md` 第一節。

## 第 2 步：製作美術圖（開需求 → GPT 產出 → 勾選）

0. **先排優先級，照順序做**（目的是快速掌握整體設計質感）：
   - P0 全局視覺：面積大、決定第一眼、製作直接的（場景背景手機＋桌機、主標、主要道具外框與底座、主按鈕、色票）→ 最先做，
     全部到位先整頁截圖確認方向。
   - P1 版面元件（彈窗、按鈕、緞帶、徽章、卡片框、底紋、分享預覽）→ P2 細節（小圖示、裝飾）。
   - P3 精修與動態：複雜、需時間打磨的（吉祥物 GIF、角色設定圖、原始檔、音效、影片）放最後慢慢雕，
     可先交靜態假圖讓頁面成形（假圖不打勾）。
   - 需求單開頭放「製作優先級」表與本案順序；勾選表每列最後一欄寫 P0～P3，`check_delivery.py` 會分級顯示進度。

1. `DESIGN_TASKS.md`：美術方向、語系規則、共通規格、**每個圖片槽一列**（檔名、外框尺寸、構圖與可放字區域、
   透明區、九宮格切法）、主視覺文字專節（三語文案、字體方向、手機可讀性、泰文上下標留白、交可編輯原始檔）、
   吉祥物比對驗收表、音效（選配）、哪些是後台內容不要做成圖。
2. `GPT_ASSET_BRIEF.md`：STYLE LOCK 共通段落＋每項英文提示詞；GPT 原生尺寸（1024²/1536×1024/1024×1536）
   與目標尺寸不同時寫明縮放裁切；吉祥物動態用 sprite sheet 3×4 + 組 GIF 腳本（400×500、24fps、≥24 幀、無縫循環、
   GIF 1-bit 透明用舞台暖色 matte）。
   **共用基準幀**：所有吉祥物 GIF 第一幀＝最後一幀＝同一張 `base-frame.png`，且每段長度相同（48 幀、2 秒）→
   無縫循環、可隨時換動作；程式（`showMascot`）在一輪結束時才切換，`check_delivery.py` 會驗證頭尾與基準幀。
3. 吉祥物形象一律以品牌包為準：Moo Rabbit `brand/moo-rabbit/`（cms_system 事業部）、熊北官方
   `mootech-asia/mootech_website` 的 `brand/moo-bear/`。生成時附四視圖＋官方 MOOTECH logo
   （藍綠→黃綠漸層的「不可能 M」，不是橘色 M）。驗收時放大檢查**背心字樣拼字**（AI 常拼錯）。
4. `DELIVERY_CHECKLIST.md`：每個交付物一列（提交☐/☑、尺寸、交付路徑、commit、審核）。GPT 只能打「提交」勾並填
   commit；「審核」欄由我們填。進度與真偽一律用腳本：
   `python3 scripts/check_delivery.py <勾選表>`（`--all` 看全部）。腳本會擋：仍是佔位圖（sha256 指紋，
   新增佔位圖後要把指紋加進 `PLACEHOLDERS`）、尺寸錯、GIF 幀數/循環、commit 裡沒有該檔或之後又改過、
   同名多副檔名。尺寸欄寫「暫緩」的列會 SKIP（例：要用即夢做的影片）；寫「（人工）」的列只檢查存在。

## 第 3 步：套用（收檔 → 換圖 → 驗證 → 上線）

1. **收檔**：對話裡貼圖會被轉檔（GIF 變成第一幀 PNG、PNG 變 WebP、透明變棋盤格），工作中途插入的訊息附圖
   甚至不會存檔。**請使用者把原檔壓成 zip 上傳**（`/root/.claude/uploads/...`），或由 GPT 直接推到交付路徑。
   收到先驗：尺寸、幀數、alpha 是否真透明、內容對應哪個狀態（抽關鍵幀拼成總覽圖看）。
2. **換圖**：放到交付路徑、刪掉同名佔位檔、改 config 路徑；吉祥物確認每個狀態都切到對的 GIF 且真的在動
   （同狀態隔 300ms 截兩張比對）。
3. **驗證**（依 CLAUDE.md 回報規則）：en/ko/th × 初始/進行中/結果/次數用完，掃 `innerText`＋alt/aria/title
   的漢字（換圖標籤開著時也要掃）；手機 390 與桌機 1440 截圖目視；console 0 錯誤、無 404、無橫向捲動；
   失敗情境（後台空資料、localStorage 被封鎖、剪貼簿被拒）。
4. **勾選與上線**：commit 素材 → 勾選表打勾填該 commit → 腳本全 OK → 推 `main` → 查 `Deploy GitHub Pages`
   結論；回報附正式站網址與 pre-report-check 輸出，未驗證項目照實寫。

## 效能（手機慢網路／低階機，每個活動都要檢查）

- **吉祥物動態圖**：交付 GIF（每段約 1.2MB）→ 用 `tools/gif_to_webp.py` 轉動態 WebP（約 1/3）給網頁載入；
  頁面 load 後背景預載所有狀態（先 spinning／result 再 idle），切換時目標還沒下載完就保留目前動作——
  否則慢網路下按抽獎後角色會整隻消失好幾秒（實測 Slow 4G 轉動＋開獎全程空白）。
  `config.mascot.loopMs` 必須等於 GIF 實際每幀時長總和（用 Pillow 讀 `duration` 加總，不要用 幀數×40 推算）。
- **不要對會動的東西加 filter**：drop-shadow 加在含旋轉盤面的容器上，每一幀都要重算；陰影只加在靜止的外框圖。
- **大量同步閃爍的元件分組**：24 顆燈泡各自動畫 → 改成「熄燈層＋兩組亮燈層」只切兩組 opacity。
- 驗證：Playwright＋CDP `Emulation.setCPUThrottlingRate 6`、iPhone 裝置模擬，轉動期間量 `Performance.getMetrics` 的
  TaskDuration 與 rAF 幀間隔，逐項關閉元素比對貢獻；`Network.emulateNetworkConditions`（1.6Mbps、150ms）量載入時間與
  轉動中吉祥物是否空白。本案：主執行緒 1.85s → 0.82s，Slow 4G 載入 14.1s → 5.8s。

## 交付後常見退回項目（先自查）

- 主標只是系統字打在招牌上 → 要做成客製 Logo 字（字形、立體、融入活動主題元素），見範本需求單「主視覺文字」
- GPT 交付時順手改了版面（例：把吉祥物縮小）→ 收檔時 `git diff` 檢查 css/js/html，違反使用者已定案的版面要改回並在回報說明

- 背心字樣拼錯、logo 顏色不是官方漸層
- 角色在畫布裡太小（應佔畫布寬八成）
- 動態「忽大忽小」：整隻角色在縮放（用逐幀外框寬度量測，沒有手部動作卻變化 >10% 就退回）；鏡頭要固定
- 「透明」其實是畫上去的棋盤格
- 圖上出現中文或多餘文字；主標字超出框
- 去背白邊（暖色舞台上要放大看）
